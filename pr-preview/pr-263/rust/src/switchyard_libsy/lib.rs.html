6//! # switchyard-libsy
7//!
8//! Provider-neutral routing and multi-model orchestration for LLM applications.
9//! An [`Algorithm`] chooses one or more semantic [`LlmTarget`]s; each target's
10//! [`RoutedLlmClient`](switchyard_protocol::RoutedLlmClient) performs model I/O.
11//! This separation lets the same algorithm run in a proxy, gateway, or agent runtime.
12//!
13//! ## Setup
14//!
15//! ```toml
16//! [dependencies]
17//! switchyard-libsy = { git = "https://github.com/NVIDIA-NeMo/Switchyard.git" }
18//! switchyard-llm-client = { git = "https://github.com/NVIDIA-NeMo/Switchyard.git" }
19//! switchyard-protocol = { git = "https://github.com/NVIDIA-NeMo/Switchyard.git" }
20//! tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
21//! ```
22//!
23//! ## Quick start
24//!
25//! This complete `src/main.rs` sends one request through [`Passthrough`] to an
26//! OpenAI-compatible backend. Set `LLM_BASE_URL`, `LLM_MODEL`, and optionally
27//! `LLM_API_KEY` before running it.
28//!
29//! ```no_run
30//! use std::collections::BTreeMap;
31//! use std::error::Error;
32//! use std::sync::Arc;
33//!
34//! use switchyard_libsy::{Algorithm, LlmTarget, Passthrough};
35//! use switchyard_llm_client::{
36//!     Backend, HttpBackendConfig, ModelConfig, TranslatingLlmClient,
37//! };
38//! use switchyard_protocol::{Context, Request, completion_text, text_request};
39//!
40//! #[tokio::main]
41//! async fn main() -> Result<(), Box<dyn Error + Send + Sync>> {
42//!     let model = std::env::var("LLM_MODEL")?;
43//!     let client = Arc::new(TranslatingLlmClient::new(&[ModelConfig::new(
44//!         model.clone(),
45//!         Backend::OpenAiChat(HttpBackendConfig {
46//!             base_url: std::env::var("LLM_BASE_URL")?,
47//!             api_key: std::env::var("LLM_API_KEY").ok(),
48//!             extra_headers: BTreeMap::new(),
49//!             extra_body: BTreeMap::new(),
50//!             max_retries: 2,
51//!         }),
52//!         None,
53//!     )])?);
54//!     let algorithm: Arc<dyn Algorithm> = Arc::new(Passthrough::new(LlmTarget {
55//!         semantic_name: model,
56//!         llm_client: Some(client),
57//!     }));
58//!     let request = Request {
59//!         llm_request: text_request(None, "Explain tail latency in one sentence."),
60//!         ..Request::default()
61//!     };
62//!
63//!     let (_decisions, response) = algorithm.run(Context::default(), request).await?;
64//!     let response = response.llm_response.into_agg().await?;
65//!     println!("{}", completion_text(&response));
66//!     Ok(())
67//! }
68//! ```
69//!
70//! ## Built-in algorithms
71//!
72//! | Algorithm | Purpose |
73//! |---|---|
74//! | [`Passthrough`] | Always call one configured target. |
75//! | [`Random`] | Select among any number of targets using uniform or weighted routing. |
76//! | [`LlmTaskClassifier`] | Ask a judge model to choose an efficient or capable target. |
77//! | [`StageRouter`] | Route coding-agent turns from tool and progress signals, with an optional judge fallback. |
78//!
79//! [`Noop`] is a test helper, not a production routing algorithm.
80//!
81//! ## Core concepts
82//!
83//! - [`Algorithm`] owns routing policy and can make one or more model calls per request.
84//! - [`LlmTarget`] gives an algorithm a semantic target name and optional default client.
85//! - [`Request`](switchyard_protocol::Request) and
86//!   [`Response`](switchyard_protocol::Response) carry the provider-neutral conversation.
87//! - [`Decision`](switchyard_protocol::Decision) records each selected target and its reasoning.
88//!
89//! ## Execution modes
90//!
91//! Use [`Algorithm::run`] when targets have default clients. Use
92//! [`Algorithm::run_stream`] when the host owns model transport and needs to fulfill each
93//! [`Step::CallLlm`] itself. Both return the same final response and decision trace.
94//!
95//! ## Operational notes
96//!
97//! Algorithm instances are shared with `Arc` and may serve concurrent requests; the full
98//! implementor contract is documented on [`Algorithm`]. Runs emit `tracing` and
99//! OpenTelemetry signals through host-installed global providers; see [`initialize_metrics`]
100//! when compatibility gauges must exist before the first request.
